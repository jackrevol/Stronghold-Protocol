# 多语言界面

界面支持简体中文（`zh-CN`）、韩语（`ko`）、英语（`en`）和日语（`ja`）。标题页、大厅、同盟等待室以及对局设置中都有语言选择器，切换立即生效，不刷新页面、不重新连接，也不清空输入或房间状态。各玩家可以独立选择语言。

首次打开时，按浏览器语言偏好选择支持的语言；手动选择后保存在 `localStorage['sp.pref.locale']`，优先于浏览器设置。不支持的语言最终回退为简体中文。区域标签（如 `ko-KR`、`en-US`、`ja-JP`）会归一化；目前所有中文区域标签都使用简体中文。存储不可用时仍可在当前页面切换。

## 当前覆盖范围

已迁移标题页、大厅、等待室、设置、难度和战场提示、全部大厅轮播提示、连接状态、客户端及服务器错误码的提示，以及公共入口按钮。页面标题、说明、横屏提示和 HTML `lang` 会一起更新。字体优先使用对应语言的系统字体，不依赖外部字体下载。

干员和召唤物的名称、分支、技能、特性、天赋、模组，以及盟约和干员特质的数据文本已支持韩语、英语和日语；干员调配与详情面板的常用标签也会切换。普通/精锐、非默认技能及模组分别使用对应文本。搜索支持当前语言名称、英文代号和中文原名。

这不是整个游戏内容的完整翻译：对局主界面中的部分标签、导入/导出提示、结算、装备/策略等其他数据、服务器发送的自由文本通知和图片内嵌文字仍可能保留原文。模块加载失败时的旧浏览器启动诊断和无 JavaScript 提示也保留中文。装饰性英文小标题不随语言切换。韩语和日语游戏名称、术语目前为项目译文，尚未核对官方本地化表。

## 给界面增加翻译

`public/js/locales/{zh-CN,ko,en,ja}.js` 是平铺的消息字典；四个文件使用相同的稳定语义键。不要把翻译后的文本用于协议、逻辑判断、存储键或资源路径。参数用 `{name}` 表示，完整句子放进字典，避免按中文语序拼接片段。

```js
import { t } from '../i18n.js';
import { useLocale } from '../ui/useLocale.js';

export function Example({ code }) {
  useLocale();
  return html`<span>${t('room.keyValue', { code })}</span>`;
}
```

翻译必须在渲染或事件处理时求值，不要在模块顶层缓存 `t()` 的结果。`useLocale()` 订阅变化而不重新挂载组件，保持输入和本地状态。不要给组件加语言相关的 `key`。`t()` 返回普通文本，交给 Preact 转义，禁止直接作为 HTML 注入；用户昵称和邀请码不翻译。

缺失消息按「当前语言 → 中文 → 调用方提供的原文 → 消息键」回退。字典支持 `{ one, other }` 等复数类别对象，由 `Intl.PluralRules` 根据 `count` 选择；数字可用 `formatNumber(value, options)`。当前字典是字符串，若采用复数对象，也应扩展字典一致性测试以验证每个分支的占位符。

## 游戏数据文本

`data/*.json` 同时供服务器、模拟器和客户端使用，不应为了显示语言改写它们。干员内容的显示层见下文；其他单条界面文本可使用 `localizedText(domain, id, field, source, params)` 在显示位置读取独立翻译，例如：

```js
localizedText('chess', chess.chessId, 'name', chess.name)
// 字典键：data.chess.<chessId>.name
```

目前模式说明使用 `data.modes.<modeId>.desc` 和 `effect0` / `effect1`。上游提示没有 ID，暂用完整原文作为 `data.tips.<原文>.text` 的标识；上游文案变化时需添加新键，否则显示新原文。记录 ID、数值、资源路径及模拟输入保持原样。追加服务器通知翻译时，应保留原文并新增消息键/参数，再在客户端解析；不能直接对任意服务器文本或玩家输入执行替换。

## 增加新语言

1. 新增完整字典并在 `public/js/i18n.js` 中导入、注册到 `catalogs` 和 `LOCALES`，扩展 `normalizeLocale()`。
2. 为新语言设置必要的系统字体和布局规则（`public/css/i18n.css`），检查长文案和小屏幕。
3. 更新 `test/ui/i18n.test.js` 的语言集合，并运行单元、静态和浏览器检查。

```sh
node --test test/ui/i18n.test.js test/client-static.test.js
SP_E2E=1 node --test test/ui/i18n.e2e.test.js
```

浏览器测试使用系统 Chrome，可通过 `CHROME_PATH` 指定路径。设置 `SP_I18N_SCREENSHOTS` 可输出各语言大厅和等待室截图。测试覆盖语言检测、字典/参数一致性、回退、受限存储、错误码、切换后输入和房间状态保持，以及刷新后的语言与会话恢复。

## 干员内容构建与显示层

`npm run build-i18n` 从 [ArknightsAssets/ArknightsGamedata](https://github.com/ArknightsAssets/ArknightsGamedata/tree/56aee3d6c5a29c3a0d192456d70d14252cbb0804) 的固定版本生成 `data/locales/{ko,en,ja}.json`。上游是社区保存的官方客户端数据；游戏文本版权仍归 Hypergryph / Yostar。缺失的区域模组和模式专用文案由 `tools/i18n/overrides.mjs` 提供项目译文，不冒充官方译文。

构建按上游表中的相同字段路径配对语言，使用完整中文模板匹配当前数据，将当前描述中的数值按占位符名称填入对应语言模板。不会把区域客户端的数值覆盖到模拟数据。覆盖层使用 `domain/recordId/field/path` 键，并保存原文校验值，避免重建数据后错误套用旧翻译。未覆盖的源文本会使构建失败，并输出 `.cache/i18n/<revision>/*-missing.json`。

```sh
npm run build-i18n                  # 下载缺失的缓存并生成
npm run build-i18n -- --refresh     # 重新下载固定版本的源表
npm run build-i18n -- --offline --check  # 离线检查生成结果是否过期
node --test test/ui/contentLocale.test.js test/ui/i18n.test.js
SP_E2E=1 node --test test/ui/i18n.e2e.test.js
```

运行时仅按需下载所选语言的一个内容文件，不访问外部翻译服务。`data.lookup()` / `data.list()` 返回缓存的显示副本；`rawData`、`data.get()` 和加载结果保留原始数据。语言切换和翻译加载完成时会通知已有数据订阅者，不重新挂载页面、不修改调配或玩家输入。缺少翻译或下载失败时回退原文，后续加载可以重试。`SOURCE_RECORD` 符号保留显示副本对应的源记录，供仍依赖原文的攻击范围规则读取；它不会进入 JSON 或网络协议。

回归检查覆盖全部受支持字段、源文一致性、占位符、非日语翻译中的汉字残留、全部技能/模组组合的属性及攻击范围一致性、语言切换缓存、下载失败重试，以及真实浏览器中的搜索和调配状态保持。
